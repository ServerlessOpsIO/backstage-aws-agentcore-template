# Creating a component

This repository was generated by the **AWS Bedrock AgentCore Agent (Python)** Backstage
template, whose source is the `backstage-aws-agentcore-template` repository.

## Form pages

| Page | Fields | Where the values go |
| --- | --- | --- |
| Component Info | Name, description, owner, domain, system, environment, account | `catalog-info.yaml`, `cfn-parameters.json`, `cfn-tags.json`, `samconfig.toml`, the repository's custom properties and the `DEPLOYMENT_ACCOUNT_ID` secret |
| Agent configuration | Instructions, model, reasoning effort, Python version, conversation memory | `src/agent/system_prompt.md`, `ModelId` and `ReasoningEffort` in `cfn-parameters.json`, the Dockerfile and workflows, and the memory resources in `template.yaml` |
| Slack | Whether to add a Slack front end, and the app's name, description, workspace and hostname | `slack/`, the `Slack app` workflow, `scripts/slack_app/`, the Lambda functions in `src/handlers/` and `src/common/`, `openapi.yaml`, the Slack resources in `template.yaml`, `Hostname` in `cfn-parameters.json`, their tests and two handbook pages. It also switches conversation memory on. |
| Spec Kit | Whether to initialize Spec Kit, and for which coding agent | The Spec Kit files in the repository |
| Copilot Cloud Agent | Whether to launch a Copilot task, and its prompt | A Copilot task on the new repository |

## What the template does

1. Reads the owner, domain, system and account entities from the catalog.
2. Copies the project skeleton and the workflows, and the Slack files when selected.
3. Initializes Spec Kit, when selected.
4. Publishes the repository to GitHub and sets the `DEPLOYMENT_ACCOUNT_ID` secret.
5. Registers the component in the catalog.
6. Launches the Copilot task, when selected. If Spec Kit was initialized for Copilot, the task
   writes the Spec Kit constitution and opens a pull request for it.

Publishing pushes to `main`, which starts the `Main` workflow. That first run fails until the
[deployment prerequisites](03-configuration.md#deployment-prerequisites) are met.
{%- if values.enable_slack_app %}

The template does not create the Slack app. Publishing also starts the `Slack app` workflow,
which checks the app definition and then fails with `app_not_recorded` until the
[first-time setup of the Slack app](08-slack-app.md#first-time-setup) is done. Until then
`Main` deploys the agent without the Slack receiving service. Afterwards, follow the
[first-time setup of Slack messaging](09-slack-messaging.md#first-time-setup).
{%- endif %}

## Naming

The component name becomes the repository name, the stack name prefix and the start of the
runtime name. The runtime is named `<component>_<branch>` with hyphens turned into underscores.
That name must begin with a letter and be 48 characters or fewer, so a long component name
leaves little room for branch names.
